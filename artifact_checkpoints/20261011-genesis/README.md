## Восстановление после нового checkout

Из корня репозитория, на Python 3.10 или новее:

```sh
python analysis/restore_published_genesis_checkpoint.py --restore
python analysis/restore_genesis_checkpoint.py --restore --restore-anchors /workspace
```

Первый помощник получает ветку данных с `origin`, проверяет закреплённый
коммит частей, SHA256 каждой части и всего bundle, импортирует исходный
коммит под отдельным локальным ref и восстанавливает только недостающие
файлы из манифеста. Активная ветка и её исходники не переключаются.
Все существующие файлы проверяются до записи; отличающиеся файлы, симлинки
и небезопасные пути отклоняются. Сохраняются байты и исполняемый режим Git;
временные метки, владельцы и дополнительные POSIX-права не воспроизводятся.

Для проверки опубликованного bundle без восстановления файлов:

```sh
python analysis/restore_published_genesis_checkpoint.py --verify
```

Получение объектов ветки данных и сборка временного bundle требуют
дополнительного свободного места. Восстановление также требует места для
исходных объектов Git и недостающих сырых данных. Помощник проверяет место
до загрузки и записи; временный собранный bundle удаляется после проверки.
На текущей машине, где полный исходный коммит и данные уже есть, применяется
проверка без загрузки, записи и сборки дополнительной копии:

```sh
python analysis/restore_published_genesis_checkpoint.py --verify-local
```

Эта локальная проверка подтверждает исходный Git-коммит и байты файлов,
но сама не подтверждает загрузку опубликованных частей с GitHub.

## Проверка небольшого архива внешних якорей

```sh
python analysis/restore_genesis_checkpoint.py --verify
```

Сравнить архив с текущими оригиналами, включая внешние файлы в `/workspace`:

```sh
python analysis/restore_genesis_checkpoint.py --verify-working-tree
```

После нового checkout в облачной среде восстановить недостающие внешние
якоря по закреплённым абсолютным путям и локальные черновики:

```sh
python analysis/restore_genesis_checkpoint.py --restore --restore-anchors /workspace
```

Можно восстановить только внешние якоря:

```sh
python analysis/restore_genesis_checkpoint.py --restore-anchors /workspace
```

Существующие одинаковые файлы принимаются; отличающиеся файлы, симлинки и
небезопасные пути отклоняются до записи. Проверяются все части, каждый
исходный файл, CRC и свободное место. Сырые данные `analysis/`
восстанавливаются из полного Git bundle и не дублируются небольшим архивом.

Абсолютные `/workspace/...` пути в замороженных драйверах не переписаны:
это сохраняет их исходные хеши. Для их запуска нужна среда с этими путями
и восстановленными якорями. Восстановление файлов не перезапускает
автоматическую цель и не выполняет новые шаги Genesis.
