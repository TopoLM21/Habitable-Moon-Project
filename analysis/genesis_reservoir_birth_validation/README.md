**Уточнение последующей диагностики:** прежний `BLOCKED_REMELT` не доказывает
физическое плавление этой массы. Текущий код использует `BLOCKED_PHASE_MAPPING`.
[Причина и исправление](../genesis_retirement_diagnosis/README.md). Числа и
описание первоначального proposal ниже сохранены как исторический результат.

# Тепло → материальный фронт: адаптер готов, реальный профиль BLOCKED_REMELT

**Проверка адаптера PASS, 72 теста PASS.** Сохранённый isolated thermal step
повторно не выполнялся. По нему пригодная для рождения механической когорты
масса равна **0**, а предлагаемое сокращение живого материала —
**3,002371985e17 кг** на 80 гранях. Текущая BE-механика такое remelt не
поддерживает: guard запрещает передавать ей предложение как готовый шаг.
Это конкретный блокер, а не отрицательный результат теплового баланса.

## Какой критерий сохранён

`genesis_reservoir_birth.py` использует прежний `lid_geometry`: первый
solidus crossing, связанный с поверхностью, с линейной интерполяцией профиля.
Это не интеграл melt fraction по всем слоям. При равных исходных массах слоёв
в каждой колонке нормированная глубина соответствует принятой координате q;
неравные слои в этом адаптере отвергаются, а не неявно переинтерпретируются.

Дальше применяется **существующий** `advance_bulk_birth`: прирост q разбивается
по слоям и создаёт последовательные новые ID; отступление сокращает deepest
reference-mass overlap. Старые formed intervals, birth brackets и ID не
заменяются. Повторно затвердевший ранее retired участок получает новый ID,
старый не оживляется. Геометрия рождения остаётся исходной spherical reference
из source packet; новые деформированные top triangles не выдаются за SphereMesh.

Прежние before-front fractions остаются буквальными accepted значениями.
Их восстановление из энтальпии отличается максимум на 1,623e−14 при guard
5e−12; замены frozen history округлённым пересчётом нет. Origin, источник,
массы, clock и reference energy должны совпадать между тепловыми endpoints.

## Почему охлаждение не дало рождения

В предыдущем тесте суммарная расплавленная масса колонок уменьшилась на
5,025769549e17 кг. Однако surface water нагрелась **1377,79405→1377,91113 К**.
Из-за этого первый поверхностно-связанный solidus crossing отступил на всех
80 гранях, несмотря на охлаждение внутренних слоёв. Поэтому уменьшение
интегральной melt mass и прирост поверхностно-связанной коры имеют здесь
разные знаки. Приравнивать 5,026e17 кг к newborn mass нельзя.

Все 800 записей каталога сохранены; у 80 предлагается уменьшить live_q_hi.
Новых ID нет. Файл с предложением содержит q-интервалы и массы, а также
энтальпию соответствующего подмножества FV-слоя. Эта энтальпия — диагностическая
часть **уже учтённого** column energy, не дополнительный источник/поток.
Latent heat нигде повторно не добавляется. Mass partition проверяется по
разности before/after фронта и сумме birth минус retirement.

## Интерфейс к механике

`prepare(before, after, legacy_raw)` возвращает sealed proposal с SHA исходного
checkpoint, обоих thermal states и **неизменной родительской памяти**.
Для роста без retirement формируется `mechanical_loading_request`: ID,
точные средние before/after температуры на live q-интервалах по существующему
`cohort_temperature`, birth temperature=solidus и ссылка на прежнюю память.
Новая память должна рассчитываться прежним `prepare_volume_loading`;
она здесь не подставляется и не объявляется продвинутой механикой.

Для реального сохранённого профиля этот request равен **null**;
`require_loading_request` выбрасывает STOP при любом retirement, даже если
кто-то переименовал статус в READY и пересчитал seal. Предложенный каталог
не принят механикой (`history_admitted_to_mechanics=false`). Удаляемые
elastic/kinetic energies оставлены **null**, не нулями. Диагностические
температуры оставшихся интервалов доступны для следующего шага реализации.

Реальный parent memory SHA:
`6edff785ae633be96f5ddc830ef85a69f76d4cb3c9b2dea59385a692f1cdad2c`.
Accepted parent остаётся 0,8684 Myr; thermal endpoint — 0,86845 Myr. Разница
часов явная: это подготовка proposal, не завершённый coupled state.

## Проверки и следующий конечный результат

Manufactured: отсутствие рождения, частичное и полное затвердевание,
рост с неизменными старыми записями, retirement без удаления ID, повторное
затвердевание без повторного использования ID; холодеющий профиль без
поверхностной связи не рождает материал. Полный adapter growth проверен
вплоть до loading request с сохранением parent memory. Реальный профиль:
проверены исходные SHA, mass partition, сериализация/continuation каталога,
remelt guard и неизменность обоих thermal файлов и canonical checkpoint.

`summary.json` содержит результат; proposal:
`/workspace/genesis-reservoir-birth-02/proposal.json`.
Команда только читает сохранённый thermal step:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
/workspace/habitable-moon-venv/bin/python -m analysis.genesis_reservoir_birth_validation.run \
  --output /workspace/genesis-reservoir-birth-NEW
```

Следующий конечный результат — консервативная обработка **реальных 80
сокращаемых интервалов**: removed radial moments, сохраняемая память,
elastic/kinetic outflows и их отдельные принимающие записи. Существующие
volume helpers умеют вычислять removed moments, но текущий BE `no_remelt`
явно запрещает переход. До проверки баланса и обновления этого допуска
запускать BE из подготовленного endpoint нельзя. Это не основание менять
критерий фронта или выдумывать стресс-free replacement старых когорт.

Исходный thermal control имел отключённые external sources; миграция увеличила
начальный нижний отток на **14,6749%**. Этот результат не является продолжением
прежнего физического прогноза. Drag/damage/thermal-work feedback остаются
отдельными блокерами; canonical/default и полная механическая эволюция не менялись.
