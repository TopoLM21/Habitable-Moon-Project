# Один работающий thermal step с реальными проводимостями

**PASS:** один изолированный шаг 50 лет из мигрированного 0,8684 Myr
состояния, до 0,86845 Myr. 2640 обменов, 0,651 с, RSS ≈155 МиБ.
79 адресных тестов PASS. Новых canonical Genesis шагов и механической
эволюции нет; production default не менялся.

## Смысл миграции и её влияние на прогноз

Прежняя Tmantle=1654,184285 К принадлежала эффективной глобальной mantle
массе 2,0294942205e24 кг: весь силикатный запас минус фиксированный surface
rock. Новая Tdeep=1645,272559 К относится к оставшейся глубокой массе
1,9883968206e24 кг после выделения **всех** колонок. Global surface больше
не содержит повторный rock — отдельным остаётся water/vapor reservoir.

Сохранены общий тепловой запас и все профили колонок; mass-partition и
thermal-projection residual равны 0 на сохранённых числах. Удельная энтальпия
новой глубокой мантии 2 137 842,109 Дж/кг положительна, melt fraction
0,408787598 допустима. Это однородная консервативная проекция остатка,
а не восстановленное историческое распределение температуры.

**Прогноз меняется.** При одинаковых профилях и геометрии начальный поток
«из глубокой мантии в колонки»:

- прежняя Tmantle: −1,058787311e14 Вт;
- новая Tdeep: −1,214163555e14 Вт;
- изменение: −1,553762438e13 Вт.

Отрицательный знак означает отток из более горячих нижних колонок в мантию;
его модуль вырос на **14,6749%**. Верхний начальный поток не меняется при
таком сравнении, потому что Tsurface и профили сохранены. Это сравнение
одних и тех же текущих площадей; оно не смешивает сдвиг T с прошлой геометрией.
При новом шаге поверхностный резервуар и deep действительно получают тепло,
поэтому последующие граничные температуры уже не будут прежними заданными.

## Геометрия и порядок операций

`tectonics/genesis_reservoir_conduction.py` читает проверенный raw legacy SHA.
Физические вершины: reference vertices + принятые displacement A.
Площади — хорды деформированных top triangles, как `_PhysicalAreaMesh`.
`dz = layer_mass/(rho*A)`, rho из исходных shell parameters;
`k=3,6 Вт/(м·К)` из того же источника, новых коэффициентов нет.

Внутренние связи: `G=kA/[0,5(dz_i+dz_{i+1})]`.
Top/bottom: `G=2kA/dz`, как полуслойные граничные расстояния прежнего
`MobileModel._conduct`. Все 2560 слоёв имеют ровно одного теплового владельца.
Extra global/cohort thermal reservoirs, изменение масс или SHA отвергаются.
Здесь реальные поверхности фиксированы на исходном snapshot; это не движущаяся
геометрия и не моделирование неизвестного положения интерфейса mantle.

1. По исходным энтальпиям вычислить температуры всех резервуаров.
2. По **одному before state** вычислить все Q=GΔTdt.
3. Одновременно записать −Q/+Q и обновить энтальпии обоих участников.
4. Инвертировать прежний закон h(T), получить новую долю расплава.

Latent heat уже в h(T), дополнительного birth-источника нет. В этом шаге
доля расплава изменяется, но новые механические когорты ещё не создаются.
Нет последовательного обновления границ с использованием уже изменённой
температуры другого слоя. CFL использует суммы всех связей; шаг равен
0,00263344 предельного (предел ≈18986,5 года), поэтому принят без substeps.

## Независимый результат и ограничения точности

Аудитор независимо строит площади через determinant Gram, температуры
силикатов через кусочную формулу h→T, водную температуру — по hot-vapor
ветви реального snapshot, и потоки через прежний flux-divergence stencil.
Он не использует значения Q из production journal для ожидаемого баланса.

За 50 лет:

| Резервуар | ΔE, Дж |
|---|---:|
| Колонки | −7,456435558e23 |
| Глубокая мантия | +1,915804401e23 |
| Поверхностная вода/пар | +5,540631168e23 |

Общий остаток 1,066453264e15 Дж укладывается в явно рассчитанную погрешность
хранения больших endpoint energies 4,681445633e15 Дж. Для **каждого** резервуара
проверка использует `4*(ulp(Ebefore)+ulp(Eafter)) + 1e−11*abs(expected exchange)`,
не нормировку малых потоков на всю планетную энергию. Максимальное отношение
ошибки к этому бюджету 0,23672. Это конечная точность binary64, не обещание
разрешить малый механический обмен в десятки Дж на огромном тепловом фоне.

Все массы неизменны, энтальпии неотрицательны. После шага температуры колонок
1576,89…2306,39 К; расплавленная масса колонок уменьшилась на 5,025770e17 кг.
Deep melt fraction выросла до 0,408787684 вследствие полученного тепла.
Локальная фаза определяется прежним h(T); отдельного допуска birth-front этим нет.
Restart побайтово идентичен, historical opening balance остаётся null.

Код и SHA outputs: `summary.json`; реальные after/restart/exchanges находятся
в `/workspace/genesis-reservoir-thermal-step-01/`. Повторный запуск CLI создаёт
ещё один isolated контроль, поэтому не нужен для обычного чтения результата:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
/workspace/habitable-moon-venv/bin/python -m analysis.genesis_reservoir_step_validation.run \
  --output /workspace/genesis-reservoir-thermal-step-NEW
```

## Условия подключения механики

Рабочий тепловой шаг уже есть. Следующий результат — адаптер phase/front и
birth на общей шкале времени с сохранением material IDs и перенесённой памяти;
пока нельзя подавать новое время в старое механическое состояние как будто оно
уже продвинуто. Затем — привязка Maxwell по когортам/слоям и проверка его
энергетического counterentry с учётом точности больших энтальпий.
Thermal-work feedback, drag/damage и внешние radiation/orbit sources остаются
отдельными задачами. В этом замкнутом тесте внешние источники выключены явно;
это не 50-летний физический прогноз всей планеты и не полная BE эволюция.
