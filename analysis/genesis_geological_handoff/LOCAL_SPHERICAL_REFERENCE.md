# Конечный локальный эталон: геометрия basal drag

База `a47272d7b00574e784cf2433837f59ec6888c54b`.
**Практическая развилка: для дальнейшей физической интерпретации мантийного
привода нужен отдельно проверенный согласованный геометрический вариант.
Одно обогащение поперечного пространства не является достаточным ремонтом;
ошибку нельзя признать приемлемой только по её абсолютным2.779Pa.**
Это не предложение нового контактного или большого объёмного solver.
Локальный вариант очень дешёв; непроверенной остаётся его совместимость
с существующей геометрией, материальным переносом и энергетикой всей модели.

## Один изготовленный локальный опыт

Взята первая исходная грань и соответствующий сферический участок при
сохранённом радиусе. Физическая поверхность эталона явно сферическая.
Используется прежний закон `traction_drag=beta P_tangent velocity`,
beta=1e14Pa s/m. Масштаб задан исходными traction amplitude и передачей
через толщину этой грани:729.636Pa, без подбора по результату.
Две известные нагрузки изготовлены из заранее заданных аналитических полей:
три rigid-rotation modes `e_i cross x/R` и один transverse mode — постоянный
вектор нормали исходной плоской грани. Всего3 или4 коэффициента.

На физической сфере для известного поля v* задана **одна** нагрузка
`tau=beta (I−nnᵀ) v*`. Сравниваются два оператора сопротивления:
нормаль сферы в каждой точке и постоянная нормаль плоской грани.
В обоих вариантах абсолютно одинаковы physical x, площадь, traction,
базис скорости, generalized F, resultant force, torque и линейный
функционал работы нагрузки. Никакая компонента tau не удалена.
Работа на разных найденных скоростях, конечно, не обязана совпадать;
сохраняется её физический функционал, а не заранее подогнанное число.

Это контролируемая проверка представлений **одной сферы**, а не подмена
существующей polyhedral-геометрии source checkpoint. В текущем коде плоские
грани объявлены физическими и нагрузка сохранена как dead traction.
Поэтому тест не доказывает наличие опечатки в текущем `facet`:
он показывает, что его нельзя одновременно интерпретировать как
согласованное представление spherical tangential traction и spherical drag.

## Результат

| Известное поле | Согласованная сфера | Плоский tangent projector |
|---|---:|---:|
| Rotation | относительная ошибка коэффициентов3.01e-15 | ошибка скорости1.765%, absolute RMS9.24e-14m/s |
| Transverse | ошибка6.07e-16 | ложная нулевая строка сопротивления при ненулевой нагрузке |

Для rotation рабочий масштаб11447.69W; плоский projector на том же
известном поле даёт11249.47W. Для transverse правильная работа/диссипация
653.311W, плоская —0. У transverse generalized force8.95393e13N в нулевой
строке: чистая локальная drag-задача с этим projector не имеет решения.
Относительный residual известного transverse поля100%, его абсолютная
норма1.3054e14N. Это не эффект малого знаменателя.

Ложный kernel — геометрический: постоянный вектор нормали плоскости
не нормален всей кривой поверхности. На сфере у него есть касательная
составляющая и физическое сопротивление, которое плоский projector теряет.
Добавление этого единственного поперечного поля выявляет проблему,
а согласованная геометрия устраняет её без изменения beta и нагрузки.

Это **не** доказательство сингулярности полного существующего shell solver:
там нормальные моды удерживаются stiffness/inertia и связями соседних
граней. Именно поэтому исходный расчёт выдаёт конечные, но сильно
сеточно-зависимые ответы. Предыдущие M/D/K и affine tests сохраняют силу.

## Проверки нагрузки, геометрии и точности эталона

Resultant force/torque интегрируются по одним и тем же физическим точкам
до выбора drag projector. Generalized work тождественно совпадает с
интегралом `tau dot v`; relative error<3.5e-16. Для rigid-rotation modes
проверено `R F_rotation = integral(x cross tau)`; для transverse mode
`F_transverse = normal_flat dot integral(tau)`.

Положительный Jacobian radial map треугольника на сферу проверен независимо
по точной площади через solid angle. Это не вычисление эталонной площади
той же квадратурой. Использованы лишь36 и100 квадратурных точек, без
сгущения реальной сетки: изменение rotation work1.74e-9, transverse
work1.02e-8. Решения воспроизводят известные коэффициенты на обеих
квадратурах. Curved4x4 operator положителен; добавленный transverse mode
не требует скрытого pinning или нового normal drag.

## Практическое значение и граница решения

Предыдущие2.779Pa — около2.8e-6 от1MPa shear threshold и2.25e-7 от
12.35MPa унаследованного RMS напряжения. Для краткого теста тепловой
релаксации это малый добавочный сигнал. Но это сопоставимо с полным
мантийным perturbation stress2.808Pa, а coarse/fine внешняя мощность
различается598022W против1148148W. Поэтому для накопления мантийного
отклика после релаксации памяти абсолютный размер не оправдывает ошибку.
Тем более RMS не ограничивает максимальную локальную ошибку порога.
На этом основании нельзя обещать практически верную тектонику или
назначить долгий горизонт без дополнительных предположений.

**Из трёх развилок выбрана отдельная согласованная геометрическая
переформулировка, требующая отдельного решения о реализации.** Малое
локальное исправление projector доказано только для изготовленной сферы;
заменить им один D в нынешнем source нельзя: это оставит M, strain L,
материальные объёмы, front geometry и сохранённую память на иной поверхности.
И простая проекция нагрузки недопустима — она уже меняла net force/torque.

Минимальная практическая спецификация следующей реализации, если она будет
выбрана: один общий physical mapping и tangent field для тяги и drag,
сначала совместимый с volume/mass/strain и source-energy transfer; тот же
тест сохранения force/torque/virtual work. Нормальное/поперечное пространство
добавлять лишь после этого, если останется численная необходимость.
Новый contact solver или произвольное общее сгущение для этого вывода
не требуются. Цена такого глобального согласования здесь не измерена;
называть его уже готовой дешёвой правкой или заведомо дорогим solver было
бы неверно. Локальный тест не закрывает остальную физическую модель.
