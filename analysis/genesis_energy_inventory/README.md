## Три подсистемы и знаки

Все числа ниже — **Дж за 100 лет**, знак «+» означает приток в названную
подсистему. Это разные контрольные объёмы; их запасы нельзя просто сложить.

### Глобальное тепло (mantle + surface)

| Член | Значение | Поле/источник |
|---|---:|---|
| ΔE mantle | −6,030070e25 | `thermal.global_state.energy[0]` |
| ΔE surface | −3,154193e24 | `energy[1]` |
| Все входящие источники | +2,491398e26 | разность `energy[2]` |
| Излучение OLR наружу | −3,125947e26 | минус разность `energy[3]` |
| Поглощённый stellar | +2,491069e26 | постоянный поток × spherical area × секунды |
| Радиогенное тепло | +3,203158e22 | точный интеграл exponential decay из параметров |
| Приливное тепло | +8,207018e20 | Δ`orbit.dissipated_energy_j`; уже внутри `energy[2]` |
| Поглощённый giant | 0, явно задано | `giant_absorbed_flux_w_m2 == 0` |

`energy[]` хранит масштабированные Дж/м²: умножение на `ENERGY_SCALE=1e12`
и сферическую reference area даёт Дж. Источники кода:
[`genesis._rhs/fluxes`](../../tectonics/genesis.py),
[`advance_orbit_thermal`](../../tectonics/genesis_onset.py).
Внутренний поток mantle→surface сокращается из суммы двух резервуаров.
Его **выведенный из баланса**, не независимо накопленный интеграл —
6,033355e25 Дж. Отдельного интегрального поля этого обмена нет.

Остаток global heat за окно −1,697179e14 Дж, или 3,02e−13 проходящей энергии;
максимум двух интервалов 5,69e−13. Это ограниченная точность записанных больших
чисел и интегрирования, а не доказанная потеря указанного количества энергии.
Такой критерий принципиально не разрешает кинетические члены порядка 55 Дж.
Совпадение orbital debit и `tidal_heat_received_j` точно на сохранённых числах.
Добавлять tidal received к global input ещё раз — двойной учёт, **в текущем
коде такого добавления не найдено**.

### Проводящие колонки

`Σ layer_mass_kg * column_enthalpy` (кг × Дж/кг) меняется на −1,443413e24 Дж;
Δ`boundary_energy_j` = −1,443413e24 Дж. Остаток 2,416e11 Дж, или 1,67e−13
проходящей энергии. `_conduct` суммирует `(flux_top-flux_bottom)*area*dt`;
flux имеет Вт/м². Top положителен внутрь колонки, bottom положителен наружу.
Отдельные интегралы top/bottom **не сохранены**.

Источник: [`MobileModel._conduct`](../../tectonics/genesis_mobile.py),
[`_advance_core`](../../tectonics/genesis_volume_thermal.py).
Колонки получают заданные температуры global reservoir, но их net boundary
не списывается из него. Они — отдельное представление того же теплового
материала, а не добавочный независимый резервуар. Сумма global+columns дала бы
неправильный контрольный объём и двойной учёт запасов, не «глобальный остаток».

### Механика K + U

`Δ(K+U) = Wext + Wthermal + Kbirth + ΔUdamage − Qdrag − QMaxwell − Nkin − Nmemory`
(в этих данных remelt outflow явно 0, сам режим remelt запрещён gate).

|---|---:|---|

| Работа basal traction | +2,470609e15 | `external_work_j = F·du` |
| Термомеханическая работа | +4,292947e17 | `thermal_work_j = −<e, C αΔT>` |
| Кинетический influx нового материала | +55,6097504 | `birth_kinetic_inflow_j` |

| Maxwell | −1,912107e18 | `physical_maxwell_j`, endpoint-оценка |
| Численная кинетическая потеря | −5057,97135 | `numerical_kinetic_j` |
| Численная потеря памяти | −3,317833e16 | `numerical_memory_j` |

Источники: [`solver.solve_trial (ledger)`](../genesis_be_candidate/solver.py),
[`prepare_volume_loading`](../../tectonics/genesis_volume_loading.py),
[`VolumeModel._phase_kinetic_flux`](../../tectonics/genesis_volume_dynamics.py),

`internal_work_j` — внутренний обмен кинетики/памяти, не дополнительный источник
в балансе K+U. Наш остаток при longdouble суммировании −284,125 Дж (7,23e−17);
он отличается от сохранённого float-остатка 768 Дж порядком суммирования.
Это не коррекция журнала. Numerical sinks остаются только диагностикой.

## Что отсутствует, а что было бы двойным учётом

| Необходимый член | Сейчас | Можно получить без новой физики? |
|---|---|---|
| −Wthermal у теплового донора | Нет встречной записи и обратной связи | Скаляр известен; получатель и термодинамически согласованная обратная связь требуют выбора модели |
| Получатель QMaxwell | Потеря памяти есть, тепло не добавлено | Распределение по когортам вычислимо из сохранённых e,C,ratio,radial moments; превращение в конкретное тепло меняет связь подсистем |
| Получатель Qdrag | Механическая потеря есть | По граням вычислимо из v и D; распределение между корой/мантией не задано |
| Приёмник −ΔUdamage | Нет отдельной fracture/free-energy/heat записи | Потеря известна; делить её между теплом и энергией повреждения произвольно нельзя |
| Резервуар работы basal traction | Предписанный внешний драйвер | Работа известна, динамический mantle-energy debit в текущем операторе отсутствует |
| Донор Kbirth | Принято comoving-включение новой массы, influx известен | Донорская кинетика расплава не представлена; нельзя подставить нулевой debit |
| Энтальпия рождения как перенос между контрольными объёмами | Отдельный transfer не сохранён | Массы и профили есть, но нужен явный выбор непересекающихся объёмов и времени/траектории переноса |
| Top/bottom conduction отдельно | Есть только net boundary | По одним endpoints однозначно не восстановить; можно собрать внутри прежнего `_conduct`/его replay, без смены закона |
| Mantle→surface integral | Только inferred из бюджета | Для независимого аудита нужно накопление потока на прежней траектории с контролем квадратуры |

За шаги родилось по 80 когорт, массы 8,052493e17 и 8,044879e17 кг. Масса
проводящих колонок не менялась: solidification маркирует уже имеющийся
материал. `rock_enthalpy = cp*T + latent*phi` уже содержит скрытую теплоту.
Добавлять заново `mass_new * latent` как отдельный источник — двойной учёт.
Нулевая исходная упругая память newborn не означает нулевую энтальпию.

Отсутствие встречных членов — **реальная незамкнутость связанной модели**,
но не доказанная арифметическая потеря внутри существующих отдельных ledger.
Изменение температур в ответ на эти члены уже является физическим coupling,
его нельзя выдать за исправление исключительно записи.

## Минимальный следующий результат и блокер длительного расчёта

Исправление только учёта: сохранять отдельный sidecar с типом контрольного
объёма, единицами, знаком, donor/recipient (включая `unassigned`), per-step
членами, схемой/квадратурой и независимым residual. Добавить отдельные top и
bottom boundary counters, а механические Q/W разложить по когортам/граням.
Ни один из этих диагностических counters не подаётся обратно в температуры;
старые checkpoints и принятая история не переписываются. Текущий аудит уже
создаёт read-only основу такого sidecar и явно оставляет неизвестные поля null.

**Ближайший физический блокер для энергетически интерпретируемой длительной
эволюции:** выбрать непересекающиеся global/column контрольные объёмы и
договориться, какой резервуар принимает Maxwell/drag/damage и отдаёт
термомеханическую работу. Если колонки остаются односторонней диагностикой,
ограниченный длительный инженерный тест возможен только с этой явной областью
применимости и stop gates; он не становится замкнутой термомеханической
эволюцией. Большое число PASS отдельных ledger этот выбор не заменяет.
Numerical dissipation никогда не является предлагаемым источником тепла.

Uncut matrix check 3,52e−15 подтверждает реализацию интегралов элемента.
**Глобальная пространственная сходимость и точность коры остаются OPEN**;
этот тест не устанавливает разрешение физических длин/изгиба планеты.
