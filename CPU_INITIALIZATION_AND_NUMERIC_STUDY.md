# CPU: однократная подготовка и исследование численных участков

Исторический отчёт этапа 2026-09-02. На следующем этапе два кандидата и
пакетный путь ячеек подключены к оптимизированному расчёту; актуальные
настройки и проверки: [CPU_NUMERIC_KERNELS.md](CPU_NUMERIC_KERNELS.md).
Ниже сохранены исходные результаты и выводы именно этого этапа.

2026-09-02. Продолжение `perf/cpu-parallel` после `0bfb810`.
Физическая модель и формат чекпойнта остаются v0.31. Стабильный worktree,
окружения Python, драйверы, пользовательские прогоны и настройки GUI не изменены.

## Что уже включено в рабочий оптимизированный режим

Раньше слой кратонной памяти строил полный `build_prototype`, но сохранял
только сетку. Затем основной runner повторял построение сетки, начальных
плит, границ и проверку жёсткого вращения.

Теперь слой кратонов запрашивает только сетку, а основной runner использует
тот же экземпляр геометрии. Фактические вызовы: **одна сетка и один прототип
вместо двух сеток и двух прототипов**. Загрузка чекпойнта и проверки модели
не удалены; основной прототип по-прежнему проходит прежнюю проверку.

Кэш содержит только одну неизменяемую в ходе модели геометрию, а не состояние
литосферы или плиты. Ключ — subdivisions, единственный вход `build_icosphere`;
радиус применяется отдельно к единичной сфере. Смена разрешения заменяет
запись, выход из CPU-контекста очищает её. Жизненный цикл процессов, частота
чекпойнтов, безопасная пауза и порядок шагов не менялись.

В исходном CPU-режиме сохранён прежний путь. Для парного исследования есть
программный opt-out `CpuExecution(reuse_initial_mesh=False)`; нового переключателя
в GUI не требуется. Обычный оптимизированный запуск автоматически использует исправление.

## Измеренная экономия

700→720 Myr, dt=4, 20 480 ячеек, один работник переноса, четыре процесса карт,
пакетные осадки включены, приоритет below-normal. Каждый образец — отдельный
процесс; образцы выполнялись последовательно, порядок пары чередовался.
Без закрепления за ядрами и без изменения BLAS. Финальная сборка большого GIF
не входит во время промежуточного сегмента.

Лёгкие таймеры этапов дали подготовку **5.640 / 5.710 с до изменения** и
**1.886 / 1.843 с после**: около 3.8 секунды экономии в этой серии.
Это сумма непересекающихся интервалов подготовки, не сумма вложенных вызовов.

Отдельная серия без таймеров функций и без cProfile:

| Повтор | Прежняя подготовка, с | Однократная подготовка, с |
| --- | ---: | ---: |
| 1 | 35.478 | 30.922 |
| 2, обратный порядок | 35.729 | 14.664 |
| 3 | 35.956 | 29.539 |
| Медиана | **35.729** | **29.539** |

Наблюдаемое уменьшение медианы полного сегмента — около **17%**. Быстрый
образец 14.664 с не исключён, но его нельзя приписать только изменению кода.
В лёгкой инструментированной серии также была пара, где полный сегмент
после изменения оказался медленнее, несмотря на сокращение подготовки.
Разброс производительности компьютера остаётся; причина отдельно не установлена.
Старые 16-секундные измерения другой серии не являются базой этого сравнения.
Полный прогон 4.5 млрд лет на этом этапе не выполнялся; обещания нового ETA нет.

Дополнительно: свежий 0→4 Myr на **81 920 ячейках**, одна пара с лёгкими
таймерами. Полный процесс 33.132→26.349 с; подготовка 15.215→8.672 с.
Все 62 массива, метаданные/история и 47 PNG совпали. Это проверка другой
плотности и свежего старта, не измерение длительного высокодетального прогона.

## Свежий профиль численной части

Три отдельных 20-Myr сегмента с новой подготовкой. Ниже непересекающиеся
времена функций в координаторе, без cProfile. Время работников карт с ними
перекрывается: его нельзя прибавлять к таблице.

| Участок, с | 320→340, слияния | 620→640, разделения | 700→720 |
| --- | ---: | ---: | ---: |
| Цикл выбора владельца и переноса полей ячейки | **6.081** | **6.173** | **6.436** |
| Расчёт полей вулканических дуг, не рисование | 2.755 | 2.546 | 3.208 |
| Транспортная карта | 2.284 | 2.728 | 3.032 |
| Динамика плит без вложенной классификации границ | 1.374 | 1.548 | 1.809 |
| Контраст корней литосферы по соседям | 1.069 | 1.140 | 1.211 |
| Память субдукции | 1.051 | 1.150 | 1.393 |
| Вся модель осадков после предыдущего ускорения | 0.188 | 0.228 | 0.221 |
| Вся физика, включая остальные участки | 17.476 | 18.116 | 20.077 |
| Полный процесс | 27.264 | 28.503 | 30.523 |

**Самый крупный кандидат — цикл ячеек литосферы.** У 90.3–93.4% всех ячеек
в этих сегментах ровно один источник переноса. Для них перспективен отдельный
пакетный путь без маленьких сортировок и вызовов NumPy на каждой ячейке.
Это пока направление, не реализованное ускорение этого цикла. Перекрытия,
выбор победителя, общие суммы и перераспределение вещества требуют сохранения
порядка и дополнительных проверок; просто раздать весь цикл потокам нельзя.

Отдельный cProfile 700→720 уточнил ещё одну избыточность: поле отрицательной
плавучести всей сетки вычислялось **21 363 раза**, часто ради одной-двух ячеек
в выборе стороны субдукции. Его времена используются только для поиска
вызовов, не как обычные времена выполнения. Поля дуг также содержат много
локальных вычислений и общие записи в поле: это следующий, более сложный кандидат.

## Изолированные прототипы, пока НЕ включённые в физику

В `analysis/probe_numeric_candidates.py` проверены две альтернативы:

1. Пакетное усреднение трёх соседей для контраста корней. Построение массива
   соседей включено в измерение, бесплатный кэш не предполагается. Есть
   возврат к исходному коду для нерегулярного числа соседей.
2. Локальная формула плавучести вместо расчёта полного массива на каждый запрос.
   Сохранены две операции maximum и умножение float64.

На реальных состояниях 320, 620, 700 Myr результаты побитово совпали;
входные массивы и исходные файлы не изменились. По три чередующихся измерения
после проверки/прогрева для каждого варианта:

| Проверка на 20 480 ячейках | Исходный вариант | Кандидат |
| --- | ---: | ---: |
| Контраст корней по всей сетке | 56–58 мс | 3.8–4.0 мс |
| Плавучесть для 4096 выбранных ячеек | 64–67 мс | 8.2–8.4 мс |

Это примерно **14–15×** и **7.6–8.1×** для конкретных функций, не для всей
симуляции. Дополнительно проверены синтетические массивы 81 920 и 327 680
ячеек: точное совпадение сохранено. Синтетическая трёхсоседняя связность не
является планетарным прогоном; крупные выигрыши локальной формулы отражают
устранение повторных полносеточных вычислений, а не ускорение всей физики.

Рекомендуемый следующий этап: сначала внедрить эти два небольших проверенных
кандидата с полной интеграционной проверкой, затем отдельно заняться большим
циклом ячеек. После оптимизированного однопоточного варианта сравнивать
многопоточный, считая полное время сегмента. Новые пакеты и GPU для этих
прототипов не потребовались.

## Проверки и воспроизведение

- **258 тестов прошли**: геометрия, независимость состояний, смена разрешения,
  opt-out, очистка контекста, диагностические таймеры и два прототипа.
- 700→720: все 62 массива и полная история совпали с независимым стабильным
  эталоном; все 40 PNG совпали по SHA-256.
- 320→340 и 620→640: точные состояния/история, прежние события топологии,
  все 40 PNG каждого отрезка совпали с ранее проверенными результатами.
- Чекпойнт новой оптимизированной версии на 708 Myr продолжен до 720 Myr
  новым runner и **неизменённым runner стабильного worktree**. Оба точно совпали.
- Реальный Qt QProcess-контроллер: свежие 0→4→8→12 Myr, безопасная пауза
  на 4 Myr, возобновление и финализация. Все три чекпойнта, **127 PNG и 10 GIF**
  совпали с прежним эталоном. Путь и формат пользовательских чекпойнтов не изменены.
